## 平台人机验证

闲鱼在账号登录、Token 续期时可能要求人机验证（滑块、人脸）。部署前请先了解现状。

人机验证是平台的安全控制。遇到验证时请由账号所有者按官方页面完成；不要尝试绕过验证、
伪造设备身份或反复自动重试。自动化登录、会话续期和消息操作可能触发验证或账号限制；
使用前应遵守平台条款，并只连接你有权管理的账号。

## 部署失败排查

重复部署失败通常不是前端问题，优先按以下顺序检查：

1. **确认部署环境**：选择你有权管理、符合平台条款和所在地法规的环境。
2. **NAS / 低配设备**：本项目的 NAS compose 会从 `Dockerfile-cn` 构建，不再拉取上游预构建镜像；
   构建会消耗额外 CPU、内存、网络和磁盘空间。
3. **确认版本**：使用 Docker Engine 24+、Docker Compose v2；按设备余量安排构建资源。
4. **确认 `.env`**：复制 `.env.example` 后必须设置非空的强 `ADMIN_PASSWORD`，否则 Compose 会拒绝启动。
5. **确认端口**：`8080` 被占用时，在 `.env` 设置 `WEB_PORT=8081`，然后访问对应端口。
6. **确认目录权限**：容器必须能够写入 `data`、`logs` 和 `backups`。
7. **国内网络用 CN 配置**：`Dockerfile-cn` 已把 apt、pip、npm 和 Chromium 全部指向国内镜像；
   用默认 `Dockerfile` 在国内构建，通常会卡在下载 Chromium 直到超时。
8. **检查健康状态**：运行 `docker compose ps`，健康接口应返回 `healthy`。
9. **查看真实错误**：运行 `docker compose logs --tail=200 xianyu-app`，不要只看浏览器"无法访问"。
10. **清理失败构建缓存**：确认数据已备份后运行 `docker compose build --no-cache xianyu-app`，再重新启动。

常用诊断命令：

```bash
docker compose config
docker compose ps
docker compose logs --tail=200 xianyu-app
curl http://localhost:8080/health
```

## 使用流程

1. 使用首次启动时在 `.env` 设置的管理员凭据登录；如需轮换密码，请在系统设置中修改。
2. 在「账号」页面登录闲鱼账号，等待状态显示「在线」和「监听中」。
3. 在「商品」页面选择账号并同步商品。
4. 在「卡密」页面创建卡券分组并导入库存。
5. 在「自动回复」或「人工智能回复」配置客服策略。
6. 在「自动发货」中为指定商品绑定卡券，或设置账号级、全局关键词规则。
7. 在「订单」和「消息管理」页面核对实际触发结果。
8. 在「通知与日志」中排查过滤、暂停、无规则、发送失败和监听退出。
9. 自动发货异常时，在「订单 → 发货审计」检查执行步骤、库存取出量和已发送数量；完整手动发货必须填写原因。状态未核对前不要直接重发，确认结果后记录核对结论。

### 账号状态说明

- `在线 / 离线`：Cookie 和闲鱼连接状态
- `监听中`：后台消息与订单任务正在运行
- `监听异常`：任务意外退出，可重新登录或重新启用账号触发重启
- `已停用`：该账号被手动停用，不会处理消息和订单

仅显示「在线」但没有「监听中」时，请先查看「通知与日志」中的启动错误。

### 发货规则优先级

1. `指定账号 + 指定商品`：按商品 ID 精确发货，优先级最高，关键词可留空。
2. `指定账号 + 关键词`：只匹配该账号下的商品标题、详情或买家消息。
3. `全部账号 + 关键词`：通用兜底规则。

配置路径：`自动发货 → 添加发货规则 → 选择账号 → 选择商品 → 关联卡券`。

### 开放注册

「设置 → 访问与安全」里的「允许用户注册」控制登录页是否出现注册入口；
「注册邮箱验证」控制注册是否必须填邮箱验证码。验证码依赖「邮件服务」里的 SMTP 配置，
未配置 SMTP 时请关闭「注册邮箱验证」，否则用户收不到验证码、无法完成注册。

## 数据与安全

- 不要提交数据库、日志、Cookie、Token、卡密、浏览器状态和本地配置。
- 日志不得输出完整 Cookie、Authorization、签名或模型 API Key。
- 管理员下载数据库备份会生成包含 SQLite WAL 内容的一致性快照；恢复时会先创建当前库快照、检查上传数据库并通过 SQLite 在线备份写入现有连接。恢复前仍必须停止所有账号监听任务，并同时妥善保管数据库备份与 `.env` 中的密钥配置。
- 数据库版本升级前会在 `MIGRATION_BACKUP_DIR` 留存权限为 `0600` 的一致性快照；快照创建或完整性检查失败时，服务会拒绝继续启动。保留目录应位于持久化卷并定期转存到异机备份。
- Cookie、账号登录密码、AI API Key、通知渠道配置和 SMTP 密码可由 `APP_ENCRYPTION_KEY_FILE` 对应的 Fernet 密钥加密。未运行迁移脚本时，为兼容旧部署，新写入仍是明文，启动日志会警告；加密数据库在密钥缺失或错误时会拒绝启动。首次启用或轮换前先停止服务，执行 `docker compose run --rm --no-deps --entrypoint python xianyu-app -m scripts.rotate_secrets`；工具会先创建恢复快照，再迁移密钥并原子更新密钥文件。备份时需单独保护密钥文件，丢失密钥将无法恢复这些凭据。不要同时配置会覆盖密钥文件的 `APP_ENCRYPTION_KEY`。
- 发布镜像可通过 `APP_VERSION`、`APP_REVISION` 和 `IMAGE_TAG` 标记版本、提交号和可回滚标签；关于页和 `/health` 会展示构建版本/提交号。发布时使用固定版本标签，而非只依赖 `latest`，升级前保留上一镜像和数据库/密钥备份，先验证健康检查再切换流量。
- 商品批量预检仅接收 UTF-8 CSV/TSV（每批最多 5 MB、200 行），按行报告校验问题；确认后也只会导入本地草稿，不会发布商品。预检结果会绑定当前用户和账号，草稿导入仅可执行一次。
- 批量卡密扣减在 SQLite 写事务中串行化，发货明细会关联订单和账号；人工完整发货使用单独执行记录，已取出库存、已发送或状态不确定的订单不会因重复请求再次扣减或发送。
- 发货审计中的「记录核对结论」只关闭人工核对事项，不会重置执行记录，也不会自动重试或补发。仍在运行的账号任务不能结案；已停止账号的执行记录需超过 30 分钟才允许结案。
- 仅在确认未扣库存、未发送内容的失败状态下才会安全重试，最多三次；达到上限后需人工核对。
- 自动发货、发送卡密、删除商品等操作应先用测试账号验证。
- 闲鱼页面和接口可能随平台更新变化，升级后应重新验证登录、消息、商品和订单链路。
- 仍兼容旧版无盐 SHA-256 密码哈希，不建议未经额外防护直接暴露到公网。
- 验证码邮件只经由你自己配置的 SMTP 发送，发不出去直接报错，不会转交第三方接口代发。
- `ADMIN_PASSWORD` 必须在首次启动前设置，只在首次创建数据库时生效。数据库已存在时改环境变量不会改密码，请在后台改。
